# 야간 개선 실험 (2026-11-13)

중간 발표(11/13) 뒤 "어두운 곳에서 왜 못 찾나"를 확인하려고 돌린 실험 기록이다.
**효과가 없었던 것도 적어 둔다. 다시 돌리지 않으려고 쓴 문서다.**

## 한 줄 결론

**확정: 후방 영상을 학습에 넣는 것만 효과가 있었다.** 어두운 골목에서 mAP50 0.124 → 0.272.
나머지(어둡게 만든 사본, 밝기 증강 확대, 입력 960, 감마·CLAHE)는 **효과를 확인하지 못했다.**
추론 때 밝기 보정은 쓰지 않는다(오히려 내려갔다).

## 어떻게 쟀나

- val 을 **고정**했다. 모든 조건이 같은 val 을 쓴다.
  - `val_r6` — R6_04(어두운 골목) 116장. 라벨 85장 + 빈 프레임 31장, 박스 **121개**(person 97, bicycle 24)
  - `val_wiki` — Wikimedia 27장, 박스 322개(person 280, bicycle 42)
- 학습은 `yolo11n`, freeze 10, SGD, lr0 0.001, patience 20, batch 8, imgsz 640(따로 적지 않으면).
- **시드 0·1·2 세 번** 돌려 평균 ± 표준편차로 적는다. 시드 한 번만 돌린 것은 `n=1` 로 적었다.
- 놓침률 = 1 − recall.

### 왜 밝기를 의심했나

| | 장수 | 평균 밝기(0~255) | 중앙값 | 최소 | 최대 |
|---|---|---|---|---|---|
| Wikimedia (학습) | 121 | 71.6 | 70.1 | 13.7 | 134.0 |
| R6_01~03 (학습) | 81 | 70.3 | 70.2 | 64.8 | 84.5 |
| **R6_04 (val, 골목)** | 116 | **14.8** | **13.5** | 9.9 | 43.7 |

학습에 쓰는 사진은 전부 평균 70 언저리인데 val 만 14.8 이다. 다섯 배 차이다.

## 결과 1 — 학습 데이터를 바꿔 보기

A→A2 는 라벨 품질만, A2→B 는 사진 수만, B→C 는 후방 영상만 달라진다.

| 조건 | 학습 | val_r6 mAP50 | val_wiki mAP50 |
|---|---|---|---|
| 학습 전 `yolo11n` | – | 0.1398 | 0.6357 |
| A 웹 134장, 그때 라벨 | 107장 | 0.1328 ± 0.0018 | 0.6512 ± 0.0043 |
| A2 웹 134장, 지금 라벨 | 107장 | 0.1317 ± 0.0018 | 0.6506 ± 0.0044 |
| B 웹 148장 | 121장 | 0.1244 ± 0.0073 | 0.6446 ± 0.0018 |
| **C B + 후방 R6_01~03** | 202장 | **0.2717 ± 0.0460** | 0.6398 ± 0.0103 |

- **라벨 보강은 0.000 이었다.** 같은 107장에 박스를 1260 → 1479 로 늘렸는데 양쪽 val 다 그대로다.
  중간 발표 자료의 "라벨을 촘촘히 한 뒤 개선폭이 커지는 경향"은 **웹 사진으로 만든 val 에서만** 본 것이었다.
- **웹 사진 추가도 효과가 없었다**(오히려 −0.007).
- 웹 사진으로 학습하면 웹 사진에서는 오르지만(0.636 → 0.651) **어두운 골목에서는 학습 전보다 내려간다**(0.140 → 0.133).
- 후방 영상 81장만 골목에서 두 배로 올린다. 세 시드가 0.221 / 0.284 / 0.310 으로 B 의 최댓값(0.129)과 겹치지 않는다.

### 어둡게 만든 사본 — 시드 하나만 보면 속는다

`training/darken.py` 로 학습 사진을 평균 70 → 17(R6_04 와 비슷하게) 로 낮춘 사본을 더했다.

| 시드 | C | C + 사본 | 차이 |
|---|---|---|---|
| 0 | 0.2207 | 0.3869 | **+0.166** |
| 1 | 0.2844 | 0.3066 | +0.022 |
| 2 | 0.3100 | 0.2823 | **−0.028** |
| | | 평균 | **+0.054 ± 0.101** |

시드 0 만 보고 "크게 올랐다"고 말했다가 시드 1·2 에서 뒤집혔다.
**야간 실험은 처음부터 3시드로 돌린다.**

### 추론 때 밝기 보정은 쓰지 않는다

모델은 그대로 두고 입력만 밝히면 내려간다(0.2207 → 감마 0.2030, CLAHE 0.1946).
`labeler/CLAUDE.md` 에 적힌 gt100 때의 결론("야간 밝기 보정 효과 없음")이 실제 야간 영상에서도 유지된다.

**다만 "찾는 데만" 쓰는 것은 다르다.** 업로드용 얼굴 모자이크(`training/blur_for_upload.py`)는
감마로 밝혀서 사람을 찾고 모자이크는 원본에 한다. 거기서는 못 찾은 프레임이 76% → 15% 로 줄었다.
학습한 모델의 성능을 재는 것과, 가릴 얼굴을 찾는 것은 다른 문제다.

## 클래스별 — 자전거가 거의 안 잡힌다

val_r6 의 AP50 이다.

| 모델 | person | bicycle |
|---|---|---|
| 학습 전 `yolo11n` | 0.2492 | 0.0305 |
| C 시드 0 / 1 / 2 | 0.388 / 0.520 / 0.542 | 0.053 / 0.049 / 0.078 |
| C + 사본 시드 0 / 1 / 2 | 0.620 / 0.575 / 0.498 | 0.154 / 0.038 / 0.066 |

**mAP50 이 0.27 로 낮았던 가장 큰 이유는 자전거다.** 사람은 0.39~0.62 까지 올라와 있다.
그런데 val_r6 의 자전거 박스는 **24개**뿐이라, 이 숫자 자체를 믿고 말하기 어렵다.

## 측정의 한계

- `val_r6` 는 박스가 121개다. 같은 조건에서 시드만 바꿔도 mAP50 이 ±0.05 움직인다.
  **이 세트로는 0.05 수준의 차이를 가릴 수 없다.** 0.15 짜리(후방 영상)는 걸러졌고 0.05 짜리는 못 걸렀다.
- val 라벨도 결국 자동 라벨을 사람이 고친 것이다. 사람이 처음부터 그린 평가 전용 세트가 없다.

## 다시 돌리는 법

```bash
# 어둡게 만든 사본 (train 폴더에만)
python -m training.darken --images data/dataset/images/train --labels data/dataset/labels/train

# 감마·CLAHE 로 폴더 하나를 통째로 보정 (평가 세트 만들 때)
python -m training.preprocess <입력> <출력> --method gamma --gamma 1.5 --labels <라벨폴더>

# 학습 (시드만 바꿔 세 번)
python -m training.train --data <data.yaml> --name <이름>_s0 --seed 0 \
    --optimizer SGD --lr0 0.001 --patience 20 --skip-eval
```

`--optimizer` 를 주지 않으면 Ultralytics 가 `lr0` 를 **무시한다**(`engine/trainer.py`). 반드시 같이 준다.
