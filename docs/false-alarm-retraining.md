# 오경보 기록 → 재학습 절차

경보가 잘못 울린 기록을 사람이 표시해 두고, 그 사진을 "여기에는 사람도 자전거도 없다"는 **배경 자료**로 다음 학습에 넣어 같은 오경보를 줄이는 흐름이다. **자동 재학습이 아니다.** 표시와 내보내기까지는 화면이 하고, 모자이크·업로드·학습은 사람이 한다.

```
경보 발생 → 서버(SQLite)에 캡처+원본 저장 → 사람이 화면에서 "오경보로 표시"
→ 내보내기(zip) → 얼굴 모자이크 → Roboflow 업로드·Mark Null → 새 Version → 학습 → 효과 확인
```

## 1. 무엇을 오경보로 표시하나

화면의 박스는 **모델의 예측**이다(정답이 아니다). 사진을 보고 판단한다.

| 사진 속 실제 상황 | 표시 |
|---|---|
| 사람·자전거가 **없는데** 박스가 있음 (나무, 가로등, 차 불빛, 기둥) | **오경보로 표시** |
| 사람이 있고 박스가 맞음 (신뢰도가 낮아도 사람이 맞으면 정상 경보) | 표시 안 함 |
| 사람은 있는데 엉뚱한 곳에 박스가 하나 더 있음 | 표시 안 함 (빈 라벨이 사람을 "없다"고 가르치게 된다) |
| 자전거 탄 사람인데 사람만 잡힘 | 표시 안 함 (오경보가 아니라 **미탐**, 박스를 새로 달아야 한다) |

신뢰도는 오경보 여부의 기준이 아니다. 필터 "신뢰도 0.7 미만"은 의심 후보를 모으는 용도이고 최종 판단은 사진으로 한다.

## 2. 내보내기

화면의 `오경보 N건 내보내기 (zip)` 버튼 또는 `GET /api/export/false-alarms`.

```
false_alarms.zip
  images/CAP-<번호>.jpg   박스·거리선이 없는 원본 프레임 (원본이 없으면 박스가 그려진 캡처)
  labels/CAP-<번호>.txt   빈 파일 = YOLO 배경 ("사람·자전거 없음")
  manifest.csv            id, 시각, 경고 단계, 박스 수, 신뢰도, 거리, 사진 종류(raw/shot/none)
```

- 표시한 기록은 서버가 자동 삭제하지 않는다(표시를 취소하면 다시 삭제 대상).
- `manifest.csv`의 `image`가 `shot`이면 박스가 그려진 사진이라 학습에 쓰지 않는다(원본 저장 도입 전 기록).

## 3. 얼굴 모자이크 (필수)

원본 프레임에는 팀원 얼굴이 찍힌다. 외부 사이트(Roboflow)에 올리기 전에 모자이크한 사본을 만든다. 원본은 올리지 않는다.

```
python -m training.blur_for_upload --src <압축 푼 images 폴더> --out <모자이크 사본 폴더> --yunet C:/work/tools/face_detection_yunet_2023mar.onnx
```

결과의 `<out>_no_detection.txt`에 적힌 프레임은 눈으로 확인한 뒤 올린다.

## 4. Roboflow에 올리고 빈 프레임으로 처리

1. 학습 프로젝트(`alaska-night-review`)에서 Upload Data → 모자이크 사본 폴더(이미지만)를 새 배치(예: `FA_오경보_배경`)로 올린다. 라벨 txt는 올리지 않는다(Roboflow에서는 빈 라벨이 "라벨 없음"으로 들어와 Unassigned에 쌓이기 때문에 이미지만 올리고 아래에서 직접 빈 프레임으로 만든다).
2. Annotate → 올린 이미지를 열어 **Mark Null(빈 프레임)** 처리한 뒤 Dataset에 넣는다. 이전에 외부 이미지 105장 중 빈 2장을 처리한 방법과 같다.
3. `labels/`의 빈 txt는 Roboflow를 거치지 않고 Ultralytics로 직접 학습할 때 `images/`와 같은 이름으로 `labels/`에 두면 배경으로 쓰인다.

## 5. 새 Version과 학습

이전 Version과 같게 한다: Modify Classes(pedestrian·People→person, Bicycle→bicycle, 나머지 제외), Auto-Orient만, 증강 없음. 학습은 같은 설정으로 한다(yolo11n, 480, 100 epochs, patience 20, seed 0). 입력 480은 Jetson이 쓰는 크기와 같다..

배경 사진 비율의 기준은 이 프로젝트에서 검증하지 않았다. 처음에는 20~50장으로 시험하고 효과를 보고 늘린다.

## 6. 효과 확인

같은 평가 영상과 이벤트 CSV로 학습 전후를 비교한다. 입력 크기(`--imgsz`)도 전후가 **같아야** 한다(예전 640 결과와 480 결과를 섞어 비교하지 않는다).

```
python -m runner.events dump --source <영상> --model <새 모델> --imgsz 480 --out data/events/<이름>.boxes.json
python -m runner.events eval --boxes data/events/<이름>.boxes.json --events <이벤트 CSV> --calibration data/runner/calibration.json --sweep
```

볼 숫자: **빈 구간 오경보 시간(초)**과 경보 놓침(0이어야 한다). 사람·자전거 경보가 줄지 않았는지도 같이 본다.

## 7. 주의: 평가 누수

시연·평가 영상에서 나온 오경보를 학습에 넣고 **같은 영상으로 평가하면** 시험 문제를 보고 공부한 것과 같아 점수가 거짓으로 좋아진다. 학습에 넣는 오경보는 **평가에 쓰지 않은 다른 촬영분·다른 날**에서 모은다. 시연 영상의 오경보는 화면 설명용으로만 쓴다.

## 한계

- 오경보를 표시하고 학습에 넣는 것은 사람이 하는 반자동 흐름이다. 이 프로젝트에서는 아직 한 바퀴를 끝까지 돌려 보지 않았다(표시, 저장, 내보내기까지 구현·확인).
- 자전거 탄 사람이 사람으로만 잡히는 **미탐**은 이 흐름으로 해결되지 않는다. 박스를 새로 단 학습 자료가 필요하다.
- 이 파일에 쓴 명령은 레포의 도구(`training.blur_for_upload`, `runner.events`) 옵션에 맞춰 두었다.

## 발표용 한 줄
